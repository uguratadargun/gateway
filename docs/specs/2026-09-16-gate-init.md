# /gate:init — a repository's record, written once, and taught

## Goal

A repository that has just met gate has no `docs/`, no `CLAUDE.md` saying the
record is required, and nothing in the team's memory about anything built
before gate. Four repositories are in that position. `/gate:init` writes that
record from the code as it stands, and teaches it, so the first run plans
with a full brief and "how does this work" and "which decision caused this"
are answerable for work finished long before.

Out of scope: writing specs for finished work (a spec is what one run set out
to do), designing a pipeline (`/gate:design`), and pushing or opening merge
requests.

## Approach

A plugin command, not a workflow: init runs in the person's own session,
reads the repository, dispatches subagents per area, and writes files. It
commits nothing on its own; the memory step is a separate, asked-for stage,
because it writes to the whole team's memory and because `gate teach` needs
commits to read a range.

The memory step is one teach per feature, since the recorder records one
feature per run. Committing feature by feature makes `--base HEAD~1` the
whole range mechanism, so no CLI change was needed.

## Assumptions

- English documents, as everywhere else in the record.
- A repository with no git remote is initialised anyway, with decisions
  recorded unscoped; that is said rather than blocked.
- Existing documents are never overwritten, so running init twice fills gaps
  only. `CLAUDE.md` is the single exception, and only by appending the record
  section.

This change adds no code path, so both are regression checks.

## What was built

1. `plugins/gate/commands/init.md` — the command: see what is already there,
   read the repository, show the parts and let the person choose, write the
   documents, report with nothing committed, ask before committing and
   teaching one feature at a time, then say what comes next. Commands are
   auto-discovered, so no registration was needed.
2. The record around it: the design doc section, decision 0006, the
   convention reference's two mentions, the map's plugin line, the README
   paragraph, and the changelog line.
3. Version moved to 0.38.0 across `plugin.json`, `marketplace.json` and
   `GATE_VERSION`, because a file was added under `plugins/` and an install
   is cached by version.
